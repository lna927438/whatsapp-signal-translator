# HelloDog 管理后台，本地验收版

当前版本在本机运行，尚未部署。现有云端账号、真实余额和桌面聊天资料没有被本轮测试修改。

## 打开后台

双击桌面的「HelloDog 管理后台 测试版」，或运行 `scripts/start-admin-preview.ps1`。
地址为 `http://127.0.0.1:5174/admin`。仅监听本机回环地址，不对局域网或公网开放。

选择「主管理员」，点击「进入本地测试后台」。这里的身份和邮箱都是明确标记的样例，不需要真实密码。
也可选择客服、财务或内容运营，检查各自可见的页面。普通用户会被服务端拒绝进入。

测试数据库在 `verification/admin-preview-v1/data`，会保存修改；关闭浏览器不会清空记录。
运行 `scripts/stop-admin-preview.ps1` 可以停止本地服务，再打开快捷方式即可继续。
停止和重启后需要重新选择测试身份，数据库内容仍会保留。

## 已实现的操作

| 位置 | 本地可验收行为 |
| --- | --- |
| 总览 | 用户数量、正常账号、今日已扣字符、待确认订单和翻译；显示读取时间 |
| 用户与余额 | 搜索、分页、账号状态、套餐、设备登记信息、钱包与流水核对 |
| 余额调整 | 正数增加、负数扣减；显示影响账号和前后余额，填写原因后确认 |
| 翻译对账 | 查询原请求、字符数、实际扣费、缓存/免费/待确认/异常；核对原请求与用量及账本 |
| 翻译补偿 | 关联原扣费流水，一笔扣费最多补偿一次；保留原扣费和补偿两条记录 |
| 订单 | 在用户详情创建人工订单；核实收款凭证后入账；未付款订单可取消 |
| 套餐 | 新增或修改名称、字符数、币种、价格、启用状态；已创建订单保留原套餐快照 |
| 版本 | 分开管理 stable/beta；默认保存为草稿；启用要求 HTTPS 下载地址和 SHA256 |
| 公告 | 普通文本内容、重要级别、起止时间与启用状态 |
| 管理员 | 主管理员授予或撤销权限；保留至少一位正常的主管理员 |
| 操作记录 | 操作人、操作对象、原因、操作编号及修改结果，支持查询和分页 |

角色范围：主管理员拥有全部操作；管理员不能授予或撤销管理员权限；客服只能查询用户和翻译；财务可管理余额、订单和套餐；内容运营可编辑版本与公告。
以上限制同时由服务端和数据库检查，隐藏按钮不是权限边界。普通账号不能通过修改个人资料或伪造前端角色提权。

## 恢复和对账

- 同一操作始终保留同一编号。服务端在一笔数据库事务中完成余额、订单、流水和操作记录的修改。
- 回包丢失时，页面显示待确认，刷新后仍保留。点击「核对原操作」只查询原编号；已完成的操作直接恢复结果。
- 未查到完成记录时，可以按原编号明确重试；不会创建新的操作编号，也不会重复入账。
- 调整余额前核对页面读取的余额；其他操作已改变余额时拒绝旧值覆盖。正在翻译的预留字符不能被扣走。
- 收款凭证不能重复使用。只允许人工订单在这里确认收款，外部支付订单不能伪装成人工入账。
- 列表显示云端已接收的请求。完全在客户端命中的翻译缓存不会额外生成云端请求。
- 翻译记录不提供聊天正文、译文、提供商密钥或请求上下文。设备时间是上次登记时间，不冒充实时在线状态。
- 样例中刻意放入一条原文字符与用量不一致的记录，可在「翻译对账 → 需要核对」中检查。

## 当前边界

这不是线上管理入口。目前只操作独立测试数据库；真实 Supabase 登录、生产账本和管理员初始授权尚未联调。
订单支持人工登记和核对入账，不包含收单、自动支付回调或向银行卡原路退款。
版本、公告已有保存和启停管理；保存记录不会自动上传安装包、部署网站或给用户推送更新。现有下载清单、公告消费端与这些管理记录的生产联动需上线前单独接通。
设备管理先提供登记记录的查看；不声称能远程关闭 WhatsApp / Signal 客户端。

## 代码位置

- 页面和独立管理员登录：`website/src/admin/`，路由 `/admin/:section?`。
- 管理接口：`server/worker/src/admin.ts`，由现有 Worker 挂载 `/api/admin/*`。
- 数据库迁移：`supabase/migrations/20260911153034_admin_console.sql`。
- 本地服务：`tests/admin-preview.ts`，使用真实管理接口验证与 PostgreSQL 语句，身份服务为本地样例。
- 页面单独生成 `website/dist-admin-local`；生产构建输出 `website/dist`，两者分开。

## 本轮验证

数据库与接口测试覆盖普通用户越权、角色限制、重复/并发提交、余额过期、预留字符、单次补偿、订单快照、凭证复用、事务回滚、最后一位主管理员、请求对账和操作结果恢复。
浏览器测试覆盖真实页面中的搜索、余额调整、回包丢失后的刷新查询、补偿、人工订单、套餐、版本草稿、公告、操作记录、权限显示和 390 像素布局。
数据库测试使用本地 PGlite PostgreSQL 引擎；这不等同于生产 Supabase 的登录、网络、并发多连接或性能验收。
最新证据在 `verification/admin-full-tests.log` 与 `verification/admin-console/browser-result.json`；页面截图也在后一个目录。

## 之后上线的准备工作（本轮不执行）

1. 在隔离的 Supabase 测试环境应用迁移，检查 RLS、函数权限及生产数据规模下的查询性能。
2. 用已有账号进行管理员登录联调。初始主管理员必须由服务器端授权，不能通过网页自助获得。
3. 将管理接口与网站部署到测试环境，设置管理域名。拟定正式入口为 `admin.hellodog.net`，尚未配置。
4. 验证付款渠道、版本清单和公告客户端的联动，再由用户决定正式上线。

初始主管理员授权应核对用户 UUID 和邮箱后，由可信数据库操作执行对 `admin_roles` 的单行写入。不要把 service role / secret key 配入网页。
