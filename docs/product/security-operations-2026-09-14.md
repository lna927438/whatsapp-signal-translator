# HelloDog 安全运行与恢复手册

更新说明：用户随后明确授权跳过付费证书与实名认证发布 0.5.8。当前签名策略以 release-0.5.8.md 和 security/release-policy.json 为准：保留 Ed25519 更新签名及安装包内容校验，不要求 Windows Authenticode 证书。下文记录原本的本地安全实施与后续运维要求；生产激活结果以本轮发布记录为准。

本轮全部操作在本机完成，生产网站、API、Supabase、用户登录和发布元数据没有更新。本文件中的云端配置是下一次正式发布的执行清单，不是已生效配置。配套参数见 `security/activation-requirements.json`。

## 管理员与认证启用顺序

1. 账号持有人为管理员邮箱、GitHub、Cloudflare 和 Supabase 启用验证器或安全密钥，并把恢复材料放在独立的密码管理器。唯一 HelloDog 管理员仍为既有邮箱，不新增管理员。
2. 在独立 Supabase 项目先应用本轮 SQL，部署同一份经测试的 API 和后台预览。后台首次进入绑定 TOTP；管理服务检查真实登录会话、已验证因子和近期 TOTP。读操作有效期 8 小时，修改操作有效期 10 分钟。
3. 管理员遗失验证器时，使用持有人已有云平台恢复途径验证身份，撤销丢失因子及旧会话，重新绑定。不能通过公共接口降级 MFA，也不建立通用应急密码。恢复操作要登记原因、操作者、时间和操作前后状态。旧验证码/撤销会话拒绝访问已在本地验证。
4. 新密码最低 12 字符。平台套餐支持后，在 Supabase Auth 开启已泄露密码保护；未购买额外套餐。核对注册、验证码邮件、登录、密码恢复的服务端速率限制，不以客户端按钮倒计时作为保护。
5. 验证码已接入 Turnstile，并把一次性 token 传给 Supabase Auth 验证。官网配置公开 site key；客户端构建配置 `VITE_AUTH_CAPTCHA_ENABLED=true`，使用官网安全验证窗口。私钥只放 Supabase Auth。先验证新官网、客户端及密码恢复，再启用 Supabase CAPTCHA，避免旧版本无法登录。当前尚未创建或启用正式 widget。

## 密钥与发布

`security/release-policy.json` 当前禁止生产发布。普通源码提交只构建和验收；正式 Windows 发布必须手动启动并使用受保护环境。网站和 API 发布脚本也检查发布锁。

代码签名证书尚未购买。未来把 Windows 签名服务或证书接入 `WINDOWS_CSC_LINK` / `WINDOWS_CSC_KEY_PASSWORD`；受支持的硬件签名服务可在打包后签名，同样必须通过 Authenticode 和时间戳检查。私钥不放仓库。

更新元数据使用独立 Ed25519 密钥。通过 `scripts/sign-update.mjs --init-key` 在仓库外生成加密私钥，密码由安全环境提供；只将公钥和确切 Windows 发行者写入 `resources/security/update-trust.json`。先给已安装客户端分发可信公钥，再使用新密钥签名；轮换时保留新旧公钥过渡期，确认客户端覆盖后停用旧密钥。生成和发布密钥要与下载存储的上传密钥分开。

`scripts/verify-release-artifact.mjs` 在上传前验证签名、时间、版本、源码提交、安装包大小、摘要、Windows 发行者和时间戳。`--local-signature-only` 仅用于本地密码学测试，正式发布脚本没有此开关。正式公钥尚为空，当前客户端会拒绝未签名更新，而不会用旧的摘要校验降级替代。

发布前保留源码提交、全部锁文件、安装包 SHA256、签名元数据和验收结果。不要覆盖已发布的版本目录。回滚网站/API 时先确认迁移兼容；不要反向删除余额/流水表。客户端故障应发布版本号更高的修复包，不能绕过防降级校验安装任意旧包。

## 备份恢复

本地测试候选为 0.5.8-beta.2，完整证据和仍待上线验收的事项见同目录 `security-implementation-2026-09-14.md`。更新公钥存放在受完整性检查保护的应用归档中。修改发行者或公钥后必须重新构建并验收安装包，不能仅替换安装目录旁边的配置。

数据库、对象存储、安装包和必要配置分开备份。目标是最多丢失 24 小时数据、4 小时内恢复，这些是运行目标，尚未通过生产规模演练证明。加密备份保留 30 天；备份密钥独立保管，恢复材料不能仅存在同一个云账号。

`scripts/database-backup.mjs` 从 libpq 环境获取连接信息，输出 AES-256-GCM 加密备份，不打印密码。备份保留角色授权，恢复不会把私有函数重新开放给普通用户。工具限制单次数据库转储 256 MiB；超过此规模使用平台备份或流式备份流程。

恢复工具只接受本机 `hellodog_restore_*` 专用数据库，并且不自动清空目标。先验证归档完整性和密钥，再恢复，最后核对钱包、字符流水、原请求编号、RLS 和函数权限。禁止拿生产数据库做恢复测试。本轮已完成 PostgreSQL 17.11 原生导出、加密、恢复及权限核对；样例备份的临时密钥没有作为正式恢复密钥保管。

Supabase 托管角色、所有者、Auth 服务配置、Storage 对象及服务密钥不是单份逻辑数据库转储可以完整替代的。正式恢复要先建立匹配的托管环境，在隔离项目演练其角色和服务权限，再切换流量。

## 隐私和注销流程

云翻译会把消息解密后的待译文本和必要上下文发给翻译提供商。关闭某会话自动翻译可停止该会话自动请求，不能描述成所有翻译均在本机运行。

本机已完成翻译默认保留 30 天，可在隐私面板调整或清理；云端完成译文默认 30 天，待上线后由定时任务清理。原请求编号、费用和结算结果保留，防止清理后重试重复扣费。待处理任务及平台原聊天不被自动删除。旧格式本地敏感记录读取时迁移为系统加密，失败保留原文件。

后台“清理云端译文”要求主管理员近期验证、操作原因和确认，保留账务记录；仍有待确认任务时拒绝清理。该操作不删除用户在其他设备的副本。

注销用户时先确认用户身份和范围，停用账号、核对待处理费用、清理翻译内容及不再需要的备注/设备标识，导出必须保留的最少账务数据，然后按 Supabase Auth 管理流程撤销会话和删除身份。当前没有自动永久注销按钮：既有表存在级联删除，未经保留账务迁移不能直接删除 Auth 用户。登记备份到期时间；从旧备份恢复时重新执行已登记的内容清理。唯一管理员不能自助注销。

## 告警与定期检查

后台“安全与保护”展示费用保护参数和最近安全事件。费用上限、异常请求频率和过期 MFA 会生成去重事件，日志不记录聊天正文和令牌。余额变更、大范围弹窗、用户内容清理在操作记录中追踪；密码、登录、MFA 因子变更以 Supabase Auth 审计为准。

正式启用时接入平台告警：持续认证失败、管理员安全变更、大额余额调整、费用保护触发、站点内容不可用和发布变化。接收渠道需由持有人提供，本轮没有向外发送测试通知。除 HTTP 状态外，网站探测应加载后台登录界面和实际资源；本轮本地浏览器已验证后台不是空白页面。

每次发布执行密钥扫描、依赖审计、越权与费用并发测试、签名负向测试、前后台浏览器验收。每月在独立数据库演练备份恢复，核对凭据到期和恢复材料。客户规模扩大前进行有明确授权范围的独立渗透测试。
