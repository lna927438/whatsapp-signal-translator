## 当前最影响使用的问题

截图一是发送进度浮层，截图二是发送结果未确认的恢复面板。源码在准备、翻译、提交和成功阶段均调用浮层方法，因此正常发送也不断打断聊天。未确认表示客户端没有取得足够回执证据，不能据此断言消息没发出或 API 故障。

本轮已修改：

- 正常进度和成功只更新工作区状态栏，不生成聊天浮层，也不抢输入焦点。
- 异常与保留草稿只显示紧凑的“查看”入口，默认收起，用户点击后才出现详情和处理按钮，Escape 收起。
- 操作失败仍保留恢复按钮；处理中同时禁用相互冲突的核对按钮。
- 回执识别兼容 div/span 文本节点、祖先消息 ID、文字方向控制符，以及同一稳定 peer 下的联系人标题变化。
- 保留新消息 ID、相同 peer、匹配译文和导航检查。输入框清空、旧的同文消息、另一个联系人出现相同文字均不能被视为成功。
- 不自动重发状态不明的消息，不修改现有字符计费规则。

限制：这些改动已由模拟 DOM 验证；截图没有提供真实消息 DOM，无法声称所有账号的 WhatsApp 回执兼容问题均已消除。Windows 实测和长时间运行仍是上线前验收项。

## 页面和模块拆分建议

1. 工作区：账号导航、聊天区域和一行状态摘要；翻译服务名称与线路延迟不占据过多面积。
2. 账号设置：基本信息、语言与翻译、显示、网络四组，代理默认折叠。
3. 输入辅助：翻译预览、快捷回复、恢复原文由输入区主动唤出；不遮挡历史消息。
4. 任务处理：正常进度在状态栏，待核对任务集中在可主动打开的任务列表；不同联系人隔离。
5. 诊断页：将网络问题、平台回执问题、模型问题、余额和登录问题分别说明，提供针对性下一步。
6. 工程边界：逐步将当前 App.vue 分拆为导航、工具栏、状态区和设置入口；平台适配器与任务状态机保持独立，避免视觉修改改变发送行为。

## 上线前验证门槛

- 文本回归：短句、长句、换行、emoji、混合语言、引用消息、相同文本连续发送、账号/联系人切换。
- 输入回归：中文输入法、Enter、Shift+Enter、重复按键、发送中编辑、撤销与粘贴。
- 故障回归：断网、延迟、401/403/429、余额不足、代理错误、进程退出、发送后回执延迟和重启恢复。
- 计费回归：一个任务最多一次上游推理/结算；失败和重放不多扣；预览与确认发送复用同一译文时不重复付费。
- 视觉验收：1366×768 和 1920×1080、100%/125%/150% 缩放、收缩状态、键盘焦点、弱动画设置；各平台在 Windows 实机验证。
- 性能基线：记录冷启动、账号切换、翻译各阶段 p50/p95、空闲 CPU/内存和多账号长时间运行数据；先测再设合理目标，不承诺竞品宣传速度。
- 用户验收：提供未上线的预览、测试结果和待解决项，用户明确确认对应版本后才进入发布流程。
