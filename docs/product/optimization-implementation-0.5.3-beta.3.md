## 清理流程的具体保证

- 官方 Signal 删除消息前，先把不含正文的清理事件持久化到该账号独立目录，删除不会仅依赖一次临时进程消息。
- 父进程保存按用户、账号、消息编号划分的过期记录，再清理缓存、翻译正文、上下文和已完成发送副本；全部完成才确认。失败留待重试。
- 同一消息不能通过改目标语言、换请求编号、重开或清缓存绕过删除标记。不同用户或其他账号不会被连带清理。
- 翻译已提交但消息到期时，迟到结算可更新字符数和实际扣费；本机正文不恢复。相关上下文被清理的未知请求只能查询，不能拿修改后的正文重新提交原编号。
- 7/30/90 天保留期默认关闭，按 HelloDog 用户保存。预览只统计可清理的已完成记录，未发送和待确认任务保持恢复能力。
- 此保留期针对 HelloDog 翻译记录与缓存，平台聊天库、Signal 已发消息附带的原文注释和云端保留规则不由该设置清理。不要向用户声称它是所有副本的删除开关。

## 验证文件

- `all-tests.log`：全量回归。
- `signal-typecheck.log`、`signal-build.log`、`signal-package.log`：官方组件检查与打包。
- `signal-composer.json`：原生输入组件，真实网络发送明确为 false。
- `ui.json`、`restart.json`、`packaged-ui.json`、`artifact-check.json`：仅在对应检查实际完成且 passed 为 true 时作为通过证据。
- `release-manifest.json`：最终安装包/对应源码的 SHA-256、版本、范围和未通过的实机项。

此矩阵把已交付的本地修复与真实账号验收分开。四轮已有代码落地和回归覆盖，现场验收未全数完成，不能标记为全面商业发布就绪。

完整英语界面尚未完成，目前新增的是中英文快捷帮助。旧版已剪除任务的原文恢复索引也按自身时间清理；切换 HelloDog 登录时，进行中的历史读取不能返回上一用户内容。
