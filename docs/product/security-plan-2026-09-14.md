**HelloDog 安全核查与加固计划**

核查日期：2026-09-14。对象：当前 0.5.7 客户端代码与官网发布包、官网及管理后台代码、线上 Supabase 权限与安全建议。本文是实施计划，不表示下列加固已经完成。此次未修改线上配置、账号、密码或数据库数据，也未做完整渗透测试。

当前需要优先保护四类资产：用户聊天和登录状态、用户字符余额和计费记录、唯一管理员及云平台控制权、安装包和更新渠道。对日常聊天用户，安全控制应尽量自动完成；管理员登录和高风险管理操作需要更严格验证。

**已有保护应保留并补充验证**

1. 已检查的 public 表均开启 RLS，且未向匿名角色授予表权限；部分私有服务表使用撤销客户端授权的方式隔离，不能为了消除“无策略”提示而开放访问。后续应以普通用户真实令牌做跨账号访问测试，不能只看 RLS 开关。
2. 关键字符变更与翻译结算函数已限制普通用户调用；服务端有身份检查、文本长度约束、请求标识与重复结算保护。继续补齐并发、超时、缓存、重试和费用核对的场景验证。
3. 草稿、发送任务、翻译回执、缓存等指定文件已有系统加密，且相关记录加密失败不会退回明文。它们不代表所有浏览器登录数据、Signal 数据和下载附件都具有相同保护。
4. 更新已有下载域名、文件大小和 SHA256 校验；这能发现下载损坏或包不匹配，但同一个发布账号被控制后，攻击者可能同时替换文件和摘要，因此仍需发行者签名。

**第一轮：守住管理员、云端权限、余额与发布**

- 为唯一管理员绑定验证器，管理 API 验证 MFA 等级；加字符、扣字符、大范围弹窗、账号安全变更等操作要求近期二次验证。保留操作理由、操作编号、前后值和审计记录。
- 同时检查管理员邮箱、GitHub、Cloudflare、Supabase 的二次验证和恢复方式。保留一个最高权限管理员即可，自动发布与运行服务使用各自最小权限凭据。
- 保护所有管理访问入口，包括官网的 /admin 路径及备用 API 域名；不能只保护 admin.hellodog.net 的页面而让其他域名绕过 API 验证。
- 核对注册、密码重置与登录的速率限制。对异常注册/登录再触发验证码，不让正常聊天每次都过验证。认证平台的直连入口也必须具备保护。
- 完成正式源码与线上版本对应，生产仅允许明确发布。预览中验证后台登录、管理接口权限、官网和版本兼容后，提升同一份产物；保留上一份已验证版本及回滚步骤。
- 检查仓库历史、构建产物和日志是否包含服务密钥。客户端可包含公开发布密钥；翻译服务密钥、数据库服务角色密钥和发布凭据只能存在受控服务端。发现实际泄露再立即撤销并轮换相应密钥。
- 先建立每个用户及整个服务的成本上限和异常报警。达到保护阈值应暂停新增翻译并给出可理解提示，保护草稿与已完成消息。

验收：只有密码或过期二次验证不能执行高风险管理操作；普通用户不能修改余额、备注他人或发送后台通知；重复/并发请求不能重复扣字符；修改公开说明不会自动替换生产网站/API；管理员恢复及版本回滚均可在隔离环境演练。

**第二轮：加固客户端与更新**

- 先收缩预加载能力，再开启远程页面沙箱。IPC 按调用页面、主框架、账号和参数校验；不向第三方网页暴露任意文件读取、命令执行或跨账号状态访问。
- 明确允许哪些网页导航、系统协议及文件操作。默认拒绝未批准的外部协议；图片、附件下载只在用户操作时执行，检查文件名和目标路径，拒绝路径穿越，不自动运行下载文件。
- 摄像头、麦克风、屏幕共享按来源和用户当前操作授权。验证 WhatsApp/Signal 通话和媒体不会因加固失效。
- 迁移敏感设置的旧格式，优先使用系统凭据保护；加密失败时保留数据并提供恢复提示。盘点登录令牌、浏览器分区、Signal 原生数据和本地附件的实际存储方式。
- 完成安装包代码签名、签名元数据和更新验签。签名私钥与下载存储凭据分开保护；验证时间戳、版本和渠道，并设计密钥轮换。代码签名不能保证立刻消除所有 SmartScreen 或杀毒提示。
- 检查 Electron、原生 Signal 集成和依赖的安全更新，保留固定依赖版本；逐步更新并进行兼容性验证。

验收：恶意链接不能启动未批准的系统协议；第三方页面不能调用其他账号接口；没有系统加密时不会写出新的明文密钥；被篡改的更新元数据或安装包无法安装；输入/回车发送、复制图片、附件上传下载、语音视频、重开恢复和多账号隔离回归通过。

Windows 的 safeStorage 保护范围有边界：它不能阻止同一 Windows 登录用户下的所有恶意程序读取数据。应用保护还需配合系统更新、磁盘保护、最小权限和设备安全，不能宣称本地加密能对抗已经控制该电脑的程序。

**第三轮：隐私、防滥用、恢复和长期维护**

- 云翻译是在 WhatsApp/Signal 消息解密后，将待翻译文字及必要上下文发给翻译服务。隐私说明必须清楚解释这一点，不能宣称翻译环节完全不出设备。提供每个会话关闭云翻译、限制上下文及清理缓存的简单选项。
- 正常业务日志不保存聊天正文、密码、令牌或完整服务返回包。定义翻译缓存、错误日志、用户备注和审计记录各自的最短必要保留期。锁屏时默认隐藏敏感通知预览。
- 按用户、设备和 IP 综合限流；历史翻译队列设置并发与总量上限，限制上下文和输出 Tokens，处理超时、取消和重试退避。供应商费用与用户字符消耗分开记录后核对，不用固定字符/Token 比例假装真实成本。
- 明确账号注销、数据清理和备份过期的流程；财务或审计记录按实际业务要求保留，不能删除后仍无限保存聊天缓存。
- 核实线上数据库备份能力、可接受数据损失时间和恢复时间，再选择合适方案。数据库备份、对象存储、发布文件和必要配置分别检查，独立环境进行恢复演练，不覆盖生产进行测试。
- 告警至少覆盖管理员安全变更、大量余额调整、异常翻译成本、持续认证失败、发布变更和后台页面不可用。页面探测要验证实际内容，而不是只看 HTTP 200。
- 建立依赖审查、凭据到期/轮换管理、每次发布的安全回归和漏洞反馈入口。商业用户规模扩大前，由具备授权范围的独立人员完成针对身份、越权、计费和客户端桥接的渗透测试。

验收：异常请求能被限制且正常聊天保持流畅；故障期间不重复结算；日志抽样不含聊天正文和密钥；指定测试用户注销及缓存清理符合说明；备份可恢复并核对钱包/流水；出现空白后台、成本异常或管理员变更时能得到有效报警。

**实施范围与需要本人处理的事项**

目前套餐和支付系统仍不在本计划实施范围，字符余额和 API 成本的保护照常推进。绑定验证器、保管恢复材料、代码签名的个人/企业身份验证需要账号持有人参与；可能涉及费用的签名服务或云平台套餐升级，应在确认具体方案与费用后办理。其余工程调整可以先在独立环境实施、验收，再发布。

本次没有覆盖全量云平台配置、全部第三方依赖漏洞、供应商内部安全或独立渗透测试，因此不能得出“软件已经绝对安全”的结论。后续上线依据应是上述验收证据。
