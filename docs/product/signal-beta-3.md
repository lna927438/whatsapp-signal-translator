# HelloDog 0.5.2-beta.3 本地测试记录

本轮按实机反馈调整界面，并修复 Signal 的启动与基本聊天流程。没有部署线上服务，没有运行覆盖安装，没有修改旧账号资料。本轮真实组件测试均使用明确指定的空白资料目录。

| 反馈 | 本轮结果 |
| --- | --- |
| 显示设置无需折叠 | 字号、颜色和显示/隐藏译文直接放在顶部面板，与语言、翻译开关一起操作 |
| 聊天面板不显示核对信息 | 移除 WhatsApp 聊天浮层及 Signal 聊天中的待核对卡片。原任务继续保留，在“记录与恢复 → 账号与运行”中查看原文、对话和处理结果；不会自动重发 |
| Signal 一直检查中 | 修复查询状态只发出“检查中”却没有结束事件的问题；查询不会覆盖正在下载的进度；检查和准备失败后可以重试 |
| Signal 聊天入口不完整 | 增加联系人、群组、搜索、新建手机号/用户名对话、联系人同步和消息时间；切换对话保留各自草稿 |
| Signal 收发不可靠 | 同时启动只等待一份启动结果；失效账号不阻塞其他账号；支持隐藏手机号的 UUID 以及群组消息路由；严格判断发送回执，不用本机时间伪造成功 |
| Signal 后台恢复 | 意外退出后恢复接收连接；主动退出取消恢复；暂停账号时刷新联系人不会重新打开接收 |
| 首次运行下载不稳定 | 测试包内置固定版本的 signal-cli 与 Java 组件，按上游发布的 SHA-256 校验后打包；首次打开无需再下载这两项组件 |

本地修复保留了原有翻译、防重复发送和扣费记录机制。新建翻译请求的配套云端功能仍按上一轮记录的限制处理，本轮没有上线服务端。

## 仍需要手机端实测

1. 在手机 Signal 中扫码关联，确认同步到正确账号和联系人。
2. 双方各发送一条文字消息，核对联系人、原文、译文和发送结果。
3. 用群组或开启号码隐私的联系人验证消息路由。
4. 关闭到托盘后接收消息，再测试实际断网、锁屏和休眠恢复。

本轮取得关联链接，但没有替用户完成手机扫码或向真实联系人发送消息。因此不能把这些本地结果当作真实账号的双向收发验收。

当前 Signal 重点支持文字与翻译。收到附件会提示到手机查看；没有宣称支持语音通话、语音翻译或完整附件处理。历史记录从此设备接收/保存的消息中恢复，不会虚构手机上的全部旧聊天。

## 开源依据及打包

使用 [signal-cli 0.14.7](https://github.com/AsamK/signal-cli/tree/v0.14.7) 的原版进程，通过其 [JSON-RPC 接口](https://github.com/AsamK/signal-cli/blob/v0.14.7/man/signal-cli-jsonrpc.5.adoc) 完成设备关联、联系人、群组与收发。协议和联系人字段参考该版本的实现，版本提交为 82a2da59a8d32bb1638bbc3bdbb3cef8344a4fbb。

运行组件：signal-cli 0.14.7，Eclipse Temurin JRE 25.0.4.1+1（Windows x64）。原版许可、Java legal 目录和源码地址随组件保留。源码副本以独立压缩包提供，未包含任何用户会话、账号密钥或聊天内容。

`qa-evidence-beta3` 保存本轮回归日志、界面截图、独立启动及真实 Signal 组件的验证记录。安装包与组件校验值见同目录版本校验文件。
