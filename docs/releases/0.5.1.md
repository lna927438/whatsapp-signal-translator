# HelloDog 0.5.1

## Client changes

- WhatsApp send confirmation recognizes message IDs on bubble ancestors and tolerates same-conversation React rerenders after dispatch. It waits up to 15 seconds for a new matching outgoing bubble. Existing messages never confirm a new send, and an uncertain result does not trigger an automatic resend.
- The translation toolbar collapses independently for each account. Chat bounds follow its animation; keyboard focus cannot enter hidden controls.
- WhatsApp and Signal account entries use recognizable application marks. The workspace uses neutral dark surfaces, app-specific accent colors, visible focus states and reduced-motion support.
- Right-click menus prioritize common actions and move navigation and diagnostics into More. WhatsApp text fields retain native copy/paste actions and chat message menus remain available.
- A new account setup dialog configures the name, languages, translation switches, font and color before creation; the same dialog edits an existing account.
- WhatsApp accounts can use independent HTTP, HTTPS or unauthenticated SOCKS5 proxies. Users supply their own proxy. An optional test reports its exit IP and request latency. Enabled proxies do not include a direct fallback; saved changes reload that account. Disabling a proxy restores system networking.
- Proxy passwords are encrypted using Electron safeStorage, omitted from renderer account responses and never stored as plaintext. Unsupported secure storage refuses password saving. Translation API requests continue through HelloDog's service route.
- Rapid settings changes are saved in order, stale responses cannot overwrite newer field values, and completion of an old account request does not change account selection.

## Support and validation

Signal uses a separate signal-cli process; independent proxy configuration is currently unavailable for Signal and is disabled in the dialog. This release does not claim that Signal traffic uses a WhatsApp account proxy.

Validation includes TypeScript checks, production bundling, send-receipt regressions, proxy validation/routing/authentication tests, account password persistence tests and ordered-settings tests. Windows installation, real WhatsApp/Signal interaction and a user-supplied proxy still require testing on the user's computer; automated DOM tests do not establish live platform compatibility in every account.

The existing application ID and user-data migration remain unchanged, preserving prior local accounts and drafts during an ordinary upgrade.
